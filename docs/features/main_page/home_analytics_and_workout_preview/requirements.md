# Функциональные требования

## AR-01. Источник статистики

`Всего тренировок` равно числу завершённых сессий пользователя. Активные и
завершённые без сохранения сессии не учитываются.

`Последняя тренировка` определяется по максимальному `completedAt` среди
завершённых сессий, а не по порядку локального массива и не по `startedAt`.

## AR-02. Карточка общего количества

- Счётчик сохраняется.
- Под ним отображается `Всего тренировок`.
- В нижней строке отображаются `История` и шеврон `›`.
- Нажатие в любой точке карточки открывает историю.
- При значении `0` карточка остаётся доступной и открывает пустую историю.

## AR-03. Карточка последней тренировки

- Заголовок: `Последняя тренировка`.
- Значение форматируется по `ru-RU`.
- Дата и счётчик соседней карточки используют единый typography token:
  `36 px / 1 / 850`; дата визуально не меньше счётчика.
- Подписи обеих карточек имеют одинаковые кегль, насыщенность и цвет.
- Год скрывается только для даты текущего календарного года пользователя.
- `Личный рекорд` и иконка серии отсутствуют.
- При отсутствии завершённых тренировок показываются `—` и `Ещё не было`.
- Карточка не является ссылкой.

## PS-01. Выбор набора

Нажатие на набор в picker не вызывает `POST /api/workouts` и не создаёт
snapshot. Оно открывает проверку выбранного набора.

## PS-02. Данные проверки

До старта пользователь видит:

- название;
- длительность;
- сложность;
- число упражнений;
- точный порядок упражнений;
- количество подходов, цель, единицу и применяемую прогрессию.

Данные принадлежат выбранному пользователем набору.

## PS-03. Подтверждение старта

`POST /api/workouts` выполняется только после нажатия `Начать тренировку` на
экране проверки.

При успехе:

1. создаётся snapshot проверенного набора;
2. создаётся ровно одна активная сессия;
3. открывается первое упражнение, подход 1.

## PS-04. Возврат без старта

Назад возвращает в picker. Активная сессия, snapshot и подходы не создаются.
Выбранная карточка и позиция прокрутки восстанавливаются.

## PS-05. Согласованность preview и snapshot

Экран проверки передаёт на старт версию набора (`updatedAt`) или эквивалентный
revision/hash. Сервер создаёт snapshot только если версия совпадает.

Если набор изменился или был удалён после открытия:

- старт не выполняется;
- пользователь остаётся на экране;
- данные обновляются;
- показывается сообщение `Тренировка изменилась. Проверьте обновлённый состав.`

## PS-06. Активная сессия

Если к моменту подтверждения уже существует активная сессия, новая не
создаётся. Интерфейс переходит к существующей активной тренировке и сообщает:
`У вас уже есть активная тренировка`.

## PS-07. Загрузка и ошибки

- Пока загружается preview, показывается skeleton с сохранённой нижней зоной.
- При ошибке доступны `Повторить` и `Назад`.
- Во время старта CTA disabled.
- Повторное нажатие не создаёт дубль.
- При ошибке старта пользователь остаётся на preview и может повторить.

## PS-08. Пустой или недоступный набор

Если в наборе нет валидных упражнений, CTA disabled, отображается
`В этой тренировке пока нет упражнений` и действие возврата.

## PS-09. Аналитические события

Предусмотреть:

- `home_history_opened` с `source: total_workouts_card`;
- `workout_routine_preview_opened` с `routine_id`;
- `workout_routine_preview_back_clicked` с `routine_id`;
- `workout_start_confirmed` с `routine_id`;
- существующие `workout_start_succeeded` и `workout_start_failed`.

Название набора и упражнения в события не передавать.

## Критерии готовности

- Аналитические карточки соответствуют AR-01—AR-03.
- Между выбором набора и первым упражнением есть проверка состава.
- До подтверждения не существует активной сессии.
- Назад безопасно возвращает в выбор.
- Preview и созданный snapshot совпадают.
- Проверены loading, error, empty, stale revision и double tap.
