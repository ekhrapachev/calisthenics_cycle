# План выпуска

Фича: `discard_active_workout`

## Этапы

1. Реализовать доменную операцию отказа и покрыть её тестами на отсутствие
   побочных изменений статистики.
2. Добавить карточку активной тренировки с точкой продолжения.
3. Добавить sheet snapshot-состава и единый переход через `resumeWorkout()`.
4. Добавить подтверждение и действие отказа на карточку и в sheet.
5. Добавить перехват старта новой тренировки и отложенное продолжение сценария.
6. Добавить accessibility-проверки и обработку ошибок. Аналитику подключить,
   только если к выпуску появится общая инфраструктура.
7. Выпустить под feature flag, если инфраструктура флагов уже есть.

## Безопасный rollout

- Внутреннее тестирование и тестовый контур.
- 5% пользователей на 24–48 часов.
- 25% после проверки ошибок и guardrail-метрик.
- 100% при отсутствии регрессий.

Если аудитория небольшая, допустим прямой выпуск после полного QA, но технические
события ошибок всё равно должны быть доступны.

## Условия остановки

- Отказ меняет пользовательскую статистику или историю.
- Есть подтверждённая потеря прогресса без явного destructive-подтверждения.
- Частота технических ошибок превышает согласованный SLO.
- Повторная операция создаёт конфликт или блокирует старт новой тренировки.
- Карточка или sheet показывают позицию, отличную от `active.resume`.
- Состав читается из изменённого routine вместо snapshot.

## Откат

Отключить клиентские точки входа feature flag. Серверную идемпотентную операцию
можно оставить недоступной из UI. Уже отменённые тренировки не восстанавливаются,
поскольку пользователь был предупреждён о необратимости.
